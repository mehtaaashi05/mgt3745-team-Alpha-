## Findings

**The two photo ceilings disagree on purpose, and no document said so.** EVALS.md records the cap as 700,000 characters "by the Worker," which is correct about the Worker and silently leaves out that the browser's own cap is 650,000. Reading both files together put the 50,000-character gap in front of me. It is deliberate and it is good — a photo that clears the browser can never meet the Worker's 413 — but until now it lived only in two constants in two files with nothing connecting them. A later change to either number would have had nothing to check against. ADR-002 names both and says why they differ. This is the most useful thing to come out of the delegation and it came from reading, not drafting.

**The Node requirement was not discoverable from any file in the repository.** `npm test` fails on Node 20 with a syntax error before a single eval runs, and nothing in `package.json` or the README said so. "Enough to redeploy from a clean checkout" is the Phase 3 bar, and we would have missed it.

**What I could not verify, and the coherence check should be read with this in mind.** The session's network could not reach `workers.dev`, so nothing in either file is evidence about the running deployment. "Matches" in the coherence check means the repository matches the ADR. It does not mean the Worker is up. I checked the live URL and the demo sign-in by hand separately; that is a different check and it is not what the table reports.

**ADR-002 names an Approver who has not yet approved it.** I listed Rishika as Approver because she owns the integrated build and inherits the consequence, following ADR-001's pattern of Architect-driver and a second-role approver. A decision record whose Approver has not agreed is not yet a decision. She approves it in the pull request, or the line changes to whoever does.

**One thing the draft got structurally right that I want on the record as mine to defend.** It would have been easier to write ADR-002 as superseding ADR-001 — a cleaner story, visible change, obvious work done. Nothing in the build departs from ADR-001. Browser resizing is the mechanism ADR-001's own consequences predicted and declined to choose between. Marking ADR-001 Superseded would have invented a reversal we never made, and the ADR history would have been less true than the one we have.
