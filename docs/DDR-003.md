## Findings

- The draft added a `sessions` table that the first ARCHITECTURE.md schema did not have, because F1-1 says sign-up "shall sign them in." The schema section in ARCHITECTURE.md should list it.
- Invite tokens are stored only as hashes, as the ARCHITECTURE.md schema says, so the app shows the invite link only once, when the trip is created. This meets F2-1 and F2-3 but is a usability cost worth testing with real users.
- Photos are resized in the browser and stored in D1 as data URLs, capped by the Worker. This follows ADR-001's consequences; if real phone photos fail, that is an ADR-002 decision for the Architect.

## Trace to HW6

Giancarlo's HW6 ([mgt3745-hw6](https://github.com/GiancarloMartinez-Saldana/mgt3745-hw6)) gave this team's F3 rows to bolt.new and Google AI Studio and recommended bolt.new's F3 for Phase 2 ([COMPARISON.md](https://github.com/GiancarloMartinez-Saldana/mgt3745-hw6/blob/main/COMPARISON.md#decision)). Phase 2 drafted F3 with Claude instead, alongside F1, F2, and F4, because F3 needs the accounts and Worker those features add: bolt.new's F3 kept moments in browser memory with a typed name field, so adopting it would have meant replacing its storage and its member model anyway. The build carries over each HW6 lesson:

- **F3-2 must be able to fail for real.** HW6 found bolt.new's error path could never run and AI Studio could only fail through a test checkbox. Here the save goes to the Worker, a failed request keeps the photo, note, and place on screen, and the expired-session check above shows it with a real failure.
- **CSS must not override `hidden`.** Both bolt.new and this draft made the same mistake; it was fixed here with a `[hidden]` rule and recorded in SKILLS.md.
- **No name field and no invented members.** Moments are labeled with the signed-in member's username (F1), as proposed in the F3 FEATURES.md pull request that closes issue #76.
- **No `innerHTML`, globals, or extra dependencies**, the problems HW6 found in AI Studio's output.
