# TOOLS.md

Status: ACTIVE. Accountable: Aashi Mehta, Implementer. This ledger records the services the team will use, the trust boundary for each one, and the fact that no secrets or credentials live in the repository.

| Service | Trusted with | Credentials live | Crossing statement | Switching cost |
|---|---|---|---|---|
| GitHub | Public repository, source files, issues, pull requests, review history, branch protection, and commit log | Individual GitHub accounts only; no credentials in the repo | The repository is the team source of truth and the review gate for all merges. Everything that crosses into GitHub is team-visible and reviewed before it reaches `main`. | Low |
| GitHub Copilot in VS Code | Drafting and review assistance for project docs and governance files | Individual GitHub account; no secrets in repository | Copilot sees only the project content the team intentionally opens in the repo. No credentials, tokens, or real user data are permitted to cross into prompts. | Low |
| bolt.new and StackBlitz | Required specification probe using a single prompt and the team's feature specification | Specifier's StackBlitz and GitHub account; no credentials in repo | The Specifier approves the exact non-sensitive input before submission. The tool is used only for the probe, not as a production environment. | Medium |
| Cloudflare Workers / managed runtime | Browser-to-server boundary for the team's chosen architecture path, if the team builds the minimal server boundary | Credentials live in the vendor dashboard only; no secrets in the repo | Browser data leaves the browser only at the explicit API boundary and only for the approved operations recorded in the ADR. This is the named crossing in `context/ARCHITECTURE.md`. | Medium |
| Managed database (for example D1 or equivalent) | Persistence for approved data objects and product state | Credentials live in the vendor dashboard only; no secrets in repo | The database is used only for minimal records required by the product and is not a place to store unapproved credentials or personal data. | Medium |
