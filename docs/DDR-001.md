DDR-001: bolt.new Specification Probe
Task
Use the team's context/FEATURES.md as the sole project input to one bolt.new prompt, with no follow-up prompts. Record every assumption the tool made that the feature specification did not state in docs/PROBE-001.md. For each assumption, Rishika records a corresponding EARS row or an explicit exclusion in context/FEATURES.md. Do not commit generated code.

Tool and Model
bolt.new, 2026-10-07, model as reported in the bolt interface at the time of the run. Run from Rishika's account.

Economic Rationale
A human reading FEATURES.md for gaps: about 2 hours across two members, and we would miss the gaps we share. bolt run: 10 minutes. Recording findings: 50 minutes. Net saving about 1 hour, and the probe finds gaps a team reading its own spec cannot, which is the real reason to delegate it.

Trust Boundary
FEATURES.md crossed to bolt.new and StackBlitz. It contains no customer data, synthetic or real, and no credentials. No GitHub connection was made. Nothing returned was committed. Accountable: Rishika. TOOLS.md row added.

Verification Performed
Rishika and Semaj compared each screen of the generated app against FEATURES.md, identified unstated assumptions, and verified that each finding is reflected as an EARS row or explicit exclusion in FEATURES.md.

Findings
Six assumptions, five of them spec gaps, all listed in PROBE-001 with the change each produced. The probe cannot tell us whether the spec is right, only whether it is complete enough for bolt.new to not have to guess when building the feature.
